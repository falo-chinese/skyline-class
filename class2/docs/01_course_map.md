# 🗺️ 單元 01：Agent 智能邊界與指揮官思維 (Agent Boundary & GM Command)

在導入企業級 AI 時，許多主管常停留在「向 AI 提問、請 AI 寫草稿」的階段。這被稱為 **Skyline 舊階段（單點問答模式）**。

本單元將為您展示 **Skyline 新階段（端到端一條龍工作流）**，說明最高主管如何從「提示詞工程師」轉變為「AI 團隊指揮官」，理解 AI Agent 的整體能耐與能力邊界。

---

## 🚀 典範轉移：單點問答 vs. 一條龍工作流

| 評估維度 | Skyline 舊階段 (單點問答) | Skyline 新階段 (一條龍工作流) |
| :--- | :--- | :--- |
| **互動模式** | 單一對話框、即問即答、隨機發揮。 | 多角色虛擬團隊、端到端目標驅動。 |
| **主管角色** | 提示詞工程師（手動寫長 Prompt、切分段落餵 AI）。 | 指揮官（下達目標與治理標準，由 Agent 自主調用工具）。 |
| **Token 消耗效率** | 效率低、重複提問造成大量 Token 浪費，無 FinOps 概念。 | 高效、Agent 自主規劃最小路徑，自動化檢索節省 Token 成本。 |
| **作業能耐 (Power)** | 僅能處理單一文章摘要、簡單潤飾。 | 能自主讀寫檔案、調用 API、運行驗證腳本、修正錯誤。 |

---

## 🧠 Pro 等級 Agent 的核心作業能耐 (Capabilities)

為甚麼現在的主管可以「放手」讓 AI 跑完工作流？因為 Pro 等級的 Agent 具備以下三大作業能耐：

1. **自主規劃與路徑選擇 (Autonomous Planning)**
   * 當您指引一個目標（例如 `/goal: 分析 200 頁政府智慧招標書是否符合公司承諾`），Agent 會自主拆解步驟，而不需要您一步步告訴它先做什麼。
2. **多工具鏈調用與代碼執行 (Tool Use & Execution)**
   * Agent 不只會「說話」，它擁有手和腳。它可以自主搜尋地端檔案、寫出一段 Python 程式碼、並在沙盒中執行該程式碼來物理對比雲地檔案狀態，確保資料真實。
3. **自我修正與品質查核 (Self-Correction & Review)**
   * 當執行過程中遇到錯誤（例如某個套件未安裝、或比對檔案時出錯），Agent 會讀取錯誤日誌，自己修改代碼並重新執行，直到目標達成。

## 🚧 指揮官必須掌握的「能力邊界 (Boundaries)」

身為總經理，您必須清楚劃分 AI 的**作業邊界**，這也是企業導入 AI 的核心治理方針：

```text
  ┌──────────────────────────────────────────────────────────┐
  │                   總經理的決策與治理防線                  │
  │  1. 資安合規 (Data Privacy)  2. 誠信紅線 (No Hallucination)│
  └────────────────────────────┬─────────────────────────────┘
                               │ (指引與授權)
                               ▼
  ┌──────────────────────────────────────────────────────────┐
  │                 AI Agent 一條龍自動化作業區               │
  │  - 自主 RFP 拆解   - SLA 衝突初篩   - Delta 補丁生成     │
  └──────────────────────────────────────────────────────────┘
```

* **放手區域 (Delegate to Agent)**：
  大批量、高頻率、重複性高的合規比對，或需要閱讀數百頁招標書（RFP）的繁瑣工作。這部分交給 Agent，能在數分鐘內完成，且準確度超越疲憊的人類。
* **嚴守防線 (Retain Control)**：
  * **資安防線**：涉及極敏感商業機密的數據，必須限制其上雲（在本地沙盒執行 Gemini Nano）。
  * **誠信防線**：AI 絕對不能為了滿足合規而無中生有捏造公文。
  * **決策防線**：任何通過 AI 自動化產出的合規元件，在更新回公司核心資產庫（真理中心）之前，必須由您親自進行 **「一鍵收割」** 的最終簽核。
