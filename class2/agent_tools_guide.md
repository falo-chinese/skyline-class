# 🤖 Agent 工具實戰指南 (Agent Tools Guide)

本指南專為企業主管與開發同仁設計，詳細說明如何操作與調用 Pro 等級 AI Agent (特別是動態測試能耐極佳的 **Codex 技術特工**)，結合 Google NotebookLM 脈絡大腦，以一條龍方式完成招標書對帳與起草。

---

## 📂 1. 用 Agent 整理檔案 (File Prep & Intake)

在開始任何長文件分析前，必須將散落的歷史投標資料、Word、Excel 和 PDF 進行清洗與結構化。這步驟可交由技術特工 Agent 透過環境工具自動化完成：

* **自動命名與分類**：Agent 將隨意命名的檔案依據日期與類別進行重新命名。
* **提取文字與 Metadata**：自動過濾無效圖片與排版，將 docx, pdf 等內容轉換為乾淨的純文字。
* **輸出索引清單**：產生 `file_manifest.json`，作為後續知識檢索的底層目錄。

### 💬 執行 Prompt：檔案整理與結構化工具調用
```text
你現在是 Dev (Codex) 技術特工。請幫我整理本地專案目錄下的所有原始招標相關檔案（包括 pdf, docx, xlsx, txt 等）：
1. 掃描目錄並將所有檔案依據「日期_大類_原檔名」進行重新命名。
2. 自動提取出每個檔案的 Metadata（包括文件頁數、建立日期、所屬子模組）。
3. 撰寫一個 Python 腳本，將檔案以 UTF-8 編碼轉存為純文字（txt）或 JSON 結構，存放在 `staging/` 目錄中，並輸出一個 `file_manifest.json` 索引檔以利後續的 AI 檢索。
```

## 🔍 2. 比對既有招標書 (RFP Comparison & Gap Audit)

比對全新專案的 RFP 與歷史得標文件，是避免「硬性廢標條款」的關鍵防線。Agent 能利用語意比對與規則引擎動態產出差距分析：

* **強行廢標條件掃描**：自動搜尋 RFP 中有關「SLA 響應時間、實績資格、證照持有」等關鍵條款。
* **雙軌對帳比對**：比對歷史得標投標書，指出我們在技術方案或公司實績上的合規死角 (Gaps)。
* **合規警示燈號**：以紅、黃、綠燈號輸出查核表。

### 💬 執行 Prompt：RFP 與歷史得標文件差距稽核
```text
你現在是負責合規性審查的技術特工。請幫我比對剛收到的新標案需求書 `new_rfp.txt` 與我們先前得標的歷史標案 `historical_tender_won.txt`：
1. 分析新招標書中所有「硬性廢標條款」（如：SLA 響應時間、實績金額要求、團隊持證規範、技術架構標準）。
2. 與歷史得標投標書進行 Delta 比對，指出我們在技術、資歷與財務上有哪些缺失（Gaps）。
3. 輸出一個 Markdown 差距比對報告，以「合規燈號（紅、黃、綠）」標示每個項目的合規風險。
```

## 📘 3. 使用 Google NotebookLM 脈絡大腦 (Context Brain)

為避免大腦污染與 RAG 幻覺，我們使用 **Google NotebookLM** 建立地端真理中心 (SSOT) 資料流。這可以作為 Agent 的記憶大腦：

* **建立真理中心來源**：將步驟一整理好的乾淨資料（公司章程、歷史實績公文、Sophia 的證照）上傳至 NotebookLM。
* **嚴防幻覺設定**：限制問答範圍僅能來自來源。若來源沒有提及，必須拒絕虛構回答。
* **讀取分流**：讓一般查詢網關與核心資料庫隔離，確保資安安全。

### 💬 執行 Prompt：NotebookLM 脈絡大腦與防幻覺稽核
```text
你現在是 Google 生態系專家。請指導我如何為本次招標專案設定 Google NotebookLM 作為「地端真理中心 (SSOT)」資料流：
1. 在 NotebookLM 建立一個專用筆記本，命名為「地平線標案真理中心」。
2. 將剛才步驟一整理好的 `file_manifest.json` 裡面的純文字檔（如歷年標案實績、Sophia 的 PMP 證照、公司資安規章）上傳作為「來源資料 (Sources)」。
3. 設定查詢分流策略：員工與 API 中介網關僅能調用經過授權的特定來源。
4. 設計一個自動化測試 Prompts 庫，專門用來檢驗 NotebookLM 是否會產生「幻覺」，如：「若提出與來源無關的問題，必須嚴格回答『無法根據來源資料回答』」。
```

## 🖥️ 4. 檢核 AI PM 與定期排程狀態 (System Control & Audit)

地端 Windows 節點中的 AI 定期分析員（Scheduled Analyst）負責守護資安與費率。我們必須能檢核其工作與稽核狀態：

* **排程狀態檢驗**：確認 `APScheduler` 是否正常運行，如每日進度報告與敏感去識別化掃描。
* **FinOps Token 帳本審核**：掃描 SQLite 中每次 API 調用的 Token 與快取，審核是否有死循環無效呼叫。
* **防污染稽核 (Conflict Check)**：主動檢查協作區 Staging 是否與真理中心發生衝突。

### 💬 執行 Prompt：AI PM 狀態與 Checklist 定期排程檢核
```text
你現在是系統治理專家。請幫我檢核當前 Windows 地端 AI PM 平台的狀態與 Scheduled Analyst 狀態：
1. 檢查 SQLite 資料庫中 `scheduled_analyst_configs` 的排程狀態，確認 `APScheduler` 是否正常運行「資安去識別化監控」與「FinOps 成本稽核」。
2. 檢查 `FinOps & Token Check` 帳本，列出本月 API 消耗前三名的 Agent。
3. 寫一個測試腳本手動觸發 `RAG Conflict Check`，比對 Staging 協作區的變更是否會污染 SSOT 真理中心。如果發現潛在的污染衝突，主動發送警告日誌。
```

## ✍️ 5. 寫出招標書與草稿自動組裝 (Drafting & Compilation)

這是端到端流程的收割成果。利用技術特工與 NotebookLM 混合路線，進行合規投標文件章節的起草與代碼化拼裝：

* **精確文字套用**：自動檢索 NotebookLM 中真實合格的團隊證照、專案公文，取代無效幻覺。
* **Delta 補丁置入**：將解決過期證照的「人員備降方案 (Sophia)」與「2h SLA 溢價調撥同意書」組裝進技術建議書中。
* **留白人類審查**：於關鍵決策處標註 `[人類審查點]`，供主管進行最後一鍵收割 (Sync & Commit)。

### 💬 執行 Prompt：投標書草稿組裝與合規起草
```text
你現在是 Content (主力產線) 寫作專家。請幫我結合 NotebookLM 的真理脈絡，開始起草並自動組裝招標書草稿：
1. 讀取新招標案的大綱結構，針對「技術服務與 SLA 承諾」章節進行草稿起草。
2. 主動從 NotebookLM 中檢索「林淑芬 (Sophia) 的有效持證證明」以及「繁星智慧檔案專案 (350萬實績)」的精確文字，並將其填入對應的招標表格中。
3. 自動生成「系統故障 2 小時響應 (2h SLA)」的技術承諾與內部成本調撥說明。
4. 輸出最終的投標書草稿段落，並標記「[人類審核點]」以便主管進行最後的一鍵收割。
```
