# 🤖 Agent 工具使用指南 (Agent Tools Guide)

本指南專為學員與企業主管設計，詳細介紹如何靈活搭配與調用 Pro 等級的 AI Agent 工具進行開發與自動化測試。我們將重點分析 **Codex (技術特工) 在動態測試（包含 Computer Use 模擬操作與系統工具調用）中的強大實戰能耐**。

---

## 🛠️ 1. Agent 工具的核心操作模式

現代 AI Agent 不僅是「只會看程式碼」的靜態助理，而是能主動與系統環境互動的虛擬技術特工：

* **動態測試能耐 (Dynamic Sandboxed Test)**：
  傳統 RAG 僅能進行文字回答。以 **Codex (技術特工)** 為代表的 Agent，能自主在沙盒中建立執行環境，調用 Python、Bash、測試框架等實體工具，對程式碼邏輯進行全自動整合跑測。
* **Computer Use 模擬技術**：
  透過視覺模型與系統控制權（如螢幕截圖識別、滑鼠點擊、鍵盤輸入定位），Agent 可以模擬人類在操作電腦時的真實流向，自動操作測試主控台、填寫表單、觸發 Live Demo 流程並抓取錯誤日誌。

## 📋 2. 常用自動化動態測試提示詞 (Prompts)

### ⚡ 提示詞 A：端到端自動化整合跑測 (Computer Use / Tool Calling)
* **目的**：要求 Agent 自動檢測本機環境，安裝必要的 http-server，並以動態模擬（真實調用系統工具）方式執行端到端的功能測試，最後返回跑測狀態與錯誤報告。

```text
你現在是具備 Computer Use 能力的 Dev (Codex) 技術特工。請執行以下端到端動態測試：
1. 檢測本機 8080 端口是否被佔用，並在專案根目錄下啟動一個靜態網頁伺服器（使用 npx http-server 或 python3 -m http.server）。
2. 使用本機瀏覽器控制工具（或透過 Computer Use 螢幕操控模擬）打開 http://localhost:8080。
3. 定位並自動點擊「一鍵模擬測試 (Run Test)」按鈕。
4. 截圖並監控右下角「自動化測試日誌主控台」的輸出，等待所有 7 個測試步驟（科目對齊、借貸平衡、稅務調整、紙本 OCR 糾錯、代簽警告等）全部運行完畢。
5. 抓取控制台的最終狀態驗證日誌，並以繁體中文整理出測試成功/失敗的 Delta 報告。
```

### 🛡️ 提示詞 B：API 費率防呆與異常對帳稽核 (FinOps Token Audit)
* **目的**：讓 Agent 分析本地的 SQLite 資料庫（或 CSV 對帳單），動態找出是否有異常高頻調用、異常高的 Token 消耗或死循環的無效 Request。

```text
你現在是負責 FinOps 與安全審計的技術特工。請執行以下分析：
1. 讀取本機 SQLite 資料庫中最新的 `audit_logs` 表，或載入本地 CSV 對帳單。
2. 撰寫一個 Python 腳本來統計每個 Agent 帳號的每日 Token 消耗總額，以及每次請求的平均 Response Time。
3. 特別找出：單次調用 Token 數大於 100k 的異常記錄，以及響應時間超過 15 秒的異常請求。
4. 自動估算其產生的美元費率，並將檢測出的異常對帳結果生成一份 Markdown 風險通報，給出優化對策（例如將部分靜態比對任務移往本地內置 Nano 執行）。
```

## 🚀 3. 推薦的 Agent 雙軌操作流程

1. **定義邊界與需求 (SME)**：由發起人提出需要跑測的系統範圍與 SLA 響應要求。
2. **啟動 Codex 執行測試 (Dev)**：直接複製上方的「提示詞 A」發送給技術特工 Agent，使其以動態模擬與系統呼叫方式，運行端到端環境跑測。
3. **稽核與同步 SSOT (Supervisor)**：主管審查 Agent 跑測產出的測試報告，無誤後點擊一鍵收割，更新為最新的系統黄金知識庫。
