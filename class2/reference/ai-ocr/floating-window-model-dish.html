案例：載入圖片後，用浮動窗檢查細節

這個案例刻意貼近 OCR、截圖比對、教材說明的工作流：圖片留在主畫面，浮動窗放在最上層輔助查看。

為什麼這個元件實用

它不是一般彈窗，而是一個「可停在最上層的臨時工作區」。主畫面不用離開，輔助資料可以拖到旁邊、放大、縮小、半透明覆蓋。

在 OCR 情境中，使用者常需要一邊看原圖，一邊看辨識結果或 Prompt 設定。若圖片只在頁面左側，捲動或比對時容易失去上下文；浮動上層工具窗可以把圖片變成可移動參考物。

在教學情境中，老師可以把補充說明、截圖、流程圖或範例答案放進工具窗，停在畫面上方講解，不需要把整個頁面切換成另一個模式。

核心能力

  • 固定於 viewport 最上層
  • 拖曳移動與右下角 resize
  • 內容縮放固定刻度：10%、20%、50%、70%、100%、150%、200%、300%、400%
  • 圖片載入後依比例自動選擇直式或橫式尺寸組
  • 視窗大小預設：小、中、大會跟著直式/橫式切換，另有近滿版
  • 內容超出時可用水平與垂直捲動條查看
  • 透明度調整：40% 到 100%

適用場景

  • OCR 圖片放大檢查
  • 文件、截圖、表格比對
  • 教學提示窗或操作說明
  • dashboard 的臨時參考區
  • 長頁面中的浮動輔助面板

可抽換參數

  • 視窗初始位置與大小
  • 尺寸 preset 清單
  • 透明度範圍與預設值
  • 內容來源：圖片、文字、HTML 區塊
  • 是否允許拖曳、resize、縮放

模型菜名稱
Fly Window｜浮動上層工具窗元件
直覺理解
把一段內容變成可以停在畫面上方的「臨時參考窗」，讓使用者不必離開主要工作流。
核心技術
position: fixed、高 z-index、Pointer/Mouse drag、CSS resize、CSS transform: scale()、range input 控制 opacity。
邊界
這是前端 UI 元件，不負責 OCR、AI 推論或資料保存；它只處理「如何把輔助內容放在主畫面上層並可操作」。
導入方式
將 .utility-window HTML、CSS、JS 控制器複製到任一單檔教材或工具頁，將 setWindowContent() 換成自己的內容來源。
RWD 原則
桌機使用雙欄工作台；窄螢幕改單欄，浮動窗寬度收斂到 viewport 內，工具列可換行，避免小視窗按鈕被檔名擠壓。
