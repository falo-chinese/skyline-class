Knowledge Engineering Lessons Learned

從 27 份 mock dataset 文件，反推出更高價值的知識工程工作模式。

核心發現

這次原本只是要產生一包學員實作資料，但驗收後發現，更有價值的資產可能不是 27 份文件本身，而是生成它們的規則、資料模型、模板、生成器與驗證方式。

不要把長文件當作文章來寫，而要把文件當作代碼來編譯與治理。

四個發現

1. 長文件不是文章

招標書、教材包、標準答案、Prompt 指令、FALO PM 欄位，是互相引用與對帳的文件網。

2. 生成方法是高階資產

27 份教材是資產，但如何穩定生成 27 份教材，可能是更有價值的資產。

3. 與 Class02 主題一致

Class02 講知識資產化，而 aaa 的做法把文件需求轉成規則、模板、生成器與資料集。

4. Knowledge / Document as Code

知識可以被轉成結構、規則、元件與資料模型；文件可以被模板與生成器編譯。

對 AIDE 的意義

AIDE 不只是 AI 協助寫文件，而是把長文件工作轉成可規劃、可生成、可檢查、可治理的流程。

Script First

多份高度關聯文件，不要先逐份手寫。先判斷是否需要腳本化生成。

Rule First

生成文件前，先定義 RFP 門檻、實績金額、缺件、風險等級與驗收規則。

Generator First

如果文件未來會改版、重跑或複製到其他案例，生成器本身就是正式資產。

Opus 4.8 對照觀察

補查 Opus 4.8 與 Claude Code 後，可以更確定：aaa 這次先寫生成器、再編譯雙文件的做法，不是單純炫技，而是接近新一代 agentic work 的共同方向。

AI 不只是幫人完成一份成果，而是幫人建立能穩定產生成果的工作系統。
外部訊號 本案對照 共同精神
Dynamic workflows 可由 Claude 寫出 script，runtime 執行並可重跑。 create_mock_data.py 產生 27 份 Markdown。 把流程移入程式碼，而不是逐份手工產出。
Claude Code 採 Unix-style，可 pipe、script、進 CI/CD。 convert_md_to_html.py 將 source 編譯成人讀版。 AI 成為工程流程中的可組合節點。
Subagents 用獨立 context 承接大量探索與專門任務。 md、html、manifest、answer key、expected output 分層。 不同角色與交付層要分開治理。
Workflow 完成後需要驗證與回報。 對帳 Manifest、答案表、HTML parse check。 成果必須可檢查，不只是看起來完成。

因此，Class02 不應把 Antigravity 教成比較強的 AI Writer。更準確的定位是：讓企業把高價值長文件工作，從人工拼裝升級為可重跑、可檢查、可交接的文件工程流程。

這也補強 AIDE 的下一層：Workflow Codification。也就是把重複性文件任務寫成 script，讓資料規則、模板、答案、展示版與驗收流程都能被治理。

給 aaa 的後續提醒

這次做法值得保留，不要只存在於 mock_data/ 案例。後續應整理成專案層級文件，例如：

  • antigravity_working_principles.md
  • antigravity_best_practices.md
  • aide_document_engineering_principles.md

應正式沉澱：Script First、Rule First、Generator First、Markdown source + HTML compiled output、Dataset generator + display compiler、Manifest 索引、Blank template 與 answer key 同源、端到端抽樣驗收、內部版/公開版分流。

若 create_mock_data.py 與 convert_md_to_html.py 會重複使用，應整理到專案內正式工具區，例如 tools/，而不是只留在 scratch。

驗收建議

  • 核心數據是否前後一致。
  • 空白範本是否真的可練習。
  • 標準答案是否能回扣 RFP 或內部元件。
  • 風險等級是否符合常識。
  • Prompt 是否能照資料夾結構直接使用。
  • Expected outputs 是否能回推管理欄位。
  • 生成器是否值得保留為正式資產。
  • HTML 編譯結果是否能閱讀與導航，例如返回首頁、返回 README、.md 轉 .html 連結是否合理。

總結

這次 Class02 mock dataset 驗收的最大收穫是：我們原本以為要的是 27 份 Markdown，但真正值得保留的，可能是能穩定生成 27 份 Markdown 的知識工程方法。

文件需求 → 知識規則 → 資料模型 → 生成器 → 教材資料集 → 驗收與中控
