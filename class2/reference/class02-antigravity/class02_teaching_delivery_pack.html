SME 真實痛點與觀念對齊 講稿

「各位主管，我們來看一個無比真實的日常場景。當您在辦公室問同仁：『我們去年浩宇專案的報價單跟當初承諾的售後合約在哪？』您的員工一定會說：『有存啊！在雲端硬碟裡！』但當他真正去搜尋時，會跑出幾十個檔案：有 浩宇報價單_v1.xlsx、浩宇報價單_202506_final.xlsx，甚至還有 浩宇報價單_ff修改版_絕對最新.xlsx。結果，大家花了半個小時點開每個檔案肉眼比對，最後還選錯了版本，導致報價少算、公司蒙受重大損失；又或者，寫標案的資深 PM 離職了，新來的人根本不知道過去的口頭約定跟默契，每次政府有新標案進來，大家明明知道『這些實績跟公司簡介我們以前寫過幾百次了！』，但還是只能打開舊 Word 檔，手動複製貼上，再花幾天時間調整字體跟表格排版。這就是中小企業每天都在上演的『行政重力驚悚劇』。這背後只有一個核心病因，也是本堂課最重要的一句話，請大家跟我一起默念：『存在 ≠ 可利用』。很多企業主常自豪地說：『我們有做知識管理 (KM) 啊！我們買了超大 NAS，裡面存了過去十年的所有檔案！』這是一個致命的誤區。檔案靜靜地躺在硬碟深處，人走茶涼、找不到也用不了，那不叫資產，那叫數位垃圾。 在這堂課中，我們不講虛的。我們今天直接動手，盤點目前公司在『招標書』中運用到的相關資源，包含紙本、掃描 PDF、影像型歷史標案。這裡的 OCR 不是 ERP 系統整合，也不是發票或會計流程自動化；它是把歷史招標文件數位化，讓 AI 真的能搜尋、引用、拆解與重用。 接著我們再測試改檔名、去重、重新系統化歸類。這是我們將資料轉化為資產的『前置清洗（OCR + ETL）』第一步。只有把原料洗乾淨，後續的 AI 才能發揮大腦威力！」

知識資產化轉化路徑方法論 講稿

「既然知道了病因，我們要如何將『過去的累積』轉化為『未來的價值』？請大家看投影幕上這張 『知識資產化轉換引擎』 流程圖。我們今天設計了一套非常符合中小企業落地成本的「樂高積木化方法論」，分為三步：

* 第一步：OCR 數位化與內容抽取：如果歷史標案是紙本、掃描 PDF 或影像型 PDF，先用 OCR 轉成可搜尋文字。接著把過去幾百頁混亂的合約與歷史標單，抽取其中最重要、有價值的內容，轉換成一個個高價值的「核心部件（積木元件）」（例如：技術實績、保密協議、資安合規政策）。
* 第二步：個別 NotebookLM 專案前哨站：在不寫代碼的情況下，我們先將這些核心部件，建置在「個別的 NotebookLM 專案」中，讓個別專案作為我們知識庫的快速驗證區與 RAG 前哨站，搶先享受秒級 Fact-checking。
* 第三步：Antigravity 自動建置雙層索引表：我們導入 AIDE 核心特助 Antigravity。它會自動為公司生成一張「雙層知識索引表」。第一層是「整份資料的大綱骨架脈絡」，第二層是精細到「分拆元件」的細部物理路徑。

當這一切就緒後，新標案進來時，我們請 AI 把 RFP（招標規範）進行條款拆解，拆出來的元件就會自動去掃描我們的積木庫，進行全文與元件級的精準比對。這就像組裝樂高，用最安全、最精準的方式完成投標準備。」

1. 🌐 外部 2h SLA 與 🛡️ 內部 4h SLA 衝突對帳（含 FinOps 算力費率對帳）：外部要求緊急故障 2h 響應，我方母版為 4h。AI 雙軌對帳：對外在投標書中執行小幅增強改寫為合規的 2h，對內在中控亮黃燈警示調配工程師待命預算。在此同時，AI 平台亦進行 FinOps 算力治理：物理統計每次呼叫模型的耗時與計費 Token 數，以 Flash-Lite 對照 Flash 模型的雙軌費率進行雲端對帳估算，確保業務合規與算力預算皆能嚴格管控！
2. 資料真實性與實績公文缺件衝突（誠信底線）：預設 450w 的鼎盛專案（案 A）金額最高，但缺驗收公文。星河誠信紅線嚴禁 AI 偽造任何印章公文！大腦主動剔除案 A，改推薦公文 100% 齊備且達標之繁星專案 (案 C) 進行真實防禦。

工具是雙手，管理是天眼。讓 AI 載入基本母版，自動核對 RFP，產出雙軌 Checklist，由人參考與最終確認，這才是最安全的現代標案生產線！」

📥 核心知識工程：一般 Excel 檔案 (.xlsx) 導入與 PWA 雲地同步戰術

在 Class 02 中，我們教導學員處理傳統 Excel 的匯入限制。結合 FALO Prompt Hub PWA 的精神，我們可以將 Excel 導入與 Prompt 資產管理進行整合：

🔄 雲地同步戰略：本地 PWA 殼 + 雲端 GAS 派發
1. 地端 PWA 獨立視窗應用（地端安全）：學員可透過 FALO Prompt Hub PWA 在本地斷網下直接拖放 .xlsx 或 .json 插卡檔案。SheetJS 引擎在瀏覽器內核沙盒中執行解析，資料不落地、不耗 API 額度、100% 保密。
2. 雲端 Apps Script API（雲端即時派發）：管理者可將最新 Prompt 與經驗元件維護在 Google Sheets 中，一鍵部署為 Apps Script Web App。PWA 端只要填入 GAS URL，即可實時拉取全公司最新的分類與指令卡片，兼具保密性與同步便利性。

⚠️ 核心限制與痛點： 在 NotebookLM 的「新增來源」中，原生並不支援標準的 Excel (.xlsx) 二進位檔案格式（支援的檔案類型如官方說明所示：pdf, txt, md, docx, csv, pptx, epub...）。 若直接上傳 .xlsx 會產生格式不支援錯誤。為了將傳統扁平的 Excel 組織記憶灌入 AI 大腦，PM 必須掌握以下兩種各有優勢的導入重構路徑：

🟢 路徑一：雲端試算表直連法 (Google Sheets Live Link)

步驟： 將 .xlsx 檔案上傳至 Google Drive ➔ 以 Google 試算表開啟 ➔ 點選「檔案」➔「儲存為 Google 試算表」 ➔ 前往 NotebookLM 點選「Google 雲端硬碟」直接導入該 Google Sheet。

🔥 最大優勢 (PROS)：手動更新與動態自癒
這是最推薦的工業級做法。當前線 PM 在雲端試算表中隨時修改、更正或追加新的專案踩坑行數時，無須重新轉檔或二次上傳！ 只需在 NotebookLM 的該檔案來源旁點擊 🔄 重新整理來源 (Refresh Source)，大腦便會秒級快照吸收最新內容，確保企業知識庫的「動態演進」。

🟣 路徑二：AI 轉換 .csv 直接上傳法 (AI CSV Conversion)

步驟： 將原始 .xlsx 表格或截圖直接投餵給 AI 特助 ➔ 發送指令 「請幫我將這份 Excel 專案經驗庫，格式化清洗並轉譯輸出為標準的 .csv 檔案，以供 NotebookLM 讀取。」 ➔ 下載 AI 產出的 .csv ➔ 在 NotebookLM 中點選「上傳檔案」直接上傳導入。

🔥 最大優勢 (PROS)：高隱私與免設定
由於 NotebookLM 原生支援 .csv 格式，此方法免去了雲端硬碟的權限授權，非常適合對外高度保密、敏感資料不落地、或只想進行單次靜態快照特訓的專案情境。轉換完全由 AI 自動處理，SME 行政同仁 0 學習成本。
