🏢 01. 招標書作業情境說明

將真實生存的痛點，定義為明確的 「長文件工程問題」

🎯 招標標案情境：政府智慧政務數位化專案

星河準備爭取一項新台幣 500 萬元的智慧文件政務工程標案，但投標截止期限僅剩 **3 天**。面對 **120 頁** 厚重的招標規範書 (RFP)，傳統的人工處理流程正處於崩潰邊緣。

❌ 傳統人工作業崩潰點 (SME 真實痛點)

• **漏件風險**：PM 需要手讀 120 頁的細碎規範，非常容易漏掉藏在附件角落的合規要求（例如財務簽證、資安證明）。

• **語意衝突**：不同員工手動複製貼上鼎盛專案、舊教材的方法論，造成長文件寫作風格與口吻前後矛盾。

• **黑箱管理**：總經理（Grace）完全不知道目前完成了哪些、缺什麼附件、有何出標風險，只能盲目等待最後蓋章。

📋 03. 招標需求抽取表 (RFP Analysis)

大腦自主讀完 120 頁 RFP 後，為星河精準提煉出的 「四大合規核心需求」

規範編號 招標要求項目 規範細節 權重 / 扣分懲罰
REQ-01 公司基本實績證明 投標廠商須於過去 3 年內具備至少 1 案金額達 300 萬元以上之文件數位化或知識工程實績。 資格審查門檻（資格不符即退件）
REQ-02 專案執行方法論 建議書須詳述「文件數位化流程」與「知識資產化轉化路徑」，並說明品質把關機制。 評選評分核心項目（佔比 30%）
REQ-03 資訊安全防護防線 投標廠商須證明符合基本資安防護規範，並檢附資安政策切結書。 資格審查門檻（資格不符即退件）
REQ-04 財務狀況合規證明 須檢附過去 3 年經會計師簽證之財務報表，且負債比率不得高於 60%。 資格審查門檻（資格不符即退件）

📊 04. 標案合規對照矩陣 (Compliance Matrix)

建立需求與既有資產的 「映射索引 (Reference Index)」，確保出標無懈可擊

🎯 招標需求 🚦 合規狀態 🔑 既有知識資產來源 🏗️ Antigravity 執行動作
REQ-01 (基本實績) ● 100% 合規 歷史資產 `/2025年鼎盛ERP專案實績.md` 自動提取鼎盛專案 450 萬結案數據，組裝至標書第三章。
REQ-02 (方法論) ● 待組裝 方法論規章 `/skyline_pm_methodology.md` 以「流程映射與中控」為核心，自動編譯「執行方法論」草稿。
REQ-03 (資安證明) ● 100% 合規 歷史資產 `/資訊安全維護政策規範.md` 提取資安條款，組裝產生「資安切結書」草稿並放置於附件夾。
REQ-04 (財務證明) ● 高風險缺件 ⚠️ 無對應歷史檔案 **暫停動作**，於中控儀表板觸發紅燈警報。

⚠️ 05. 缺件與風險防線報告

Agent 背景自動進行合規差分檢索，為 Grace 呈交的主動避險報告

🚨

【高風險紅燈】財務合規證明缺件 (REQ-04)

嚴重威脅

**風險分析**：招標書第 18 頁規定「廠商須檢附經會計師簽證財務報表」。目前專案目錄中無任何財報 PDF 檔，若直接送件將面臨**「資格審查直接出局」**之懲罰。

💡 **避險建議**：中控台已鎖定警告。請Grace指派會計在 12 小時內將「2023-2025財務簽證.pdf」掃描並拖入大腦庫。

⚠️

【中風險黃燈】鼎盛專案結案公文未歸檔 (REQ-01)

合規瑕疵

**風險分析**：雖有結案報告 Markdown 母稿，但招標規範要求檢附「發包機關結案公文影本影印本」。目前僅有文字敘述，缺乏公文圖檔佐證。

💡 **避險建議**：請 PM 在 24 小時內找出公文原件，上傳至 `/02_歷史資產` 目錄進行知識資產化。

💎 06. 知識元件化清單 (Reusable Components)

寫標案不再從零抄寫，而是如積木般 「元件化組裝 (Componentization)」

星河過去十年的成果，已被打碎並儲存為可隨時被 Agent 調用的「知識元件」。這些是公司最具價值的無形資產：

🧩 元件 A：公司背景積木

檔名：`星河公司簡介元件.md`

包含資本額、公司統一編號、組織架構、核心榮譽。由 Agent 在所有標書首章自動調用，格式保證 100% 一致。

🧩 元件 B：方法論核心積木

檔名：`skyline_pm_methodology.md`

包含星河專屬的「流程映射與小幅增強」執行框架。直接做為標案第二章「專案執行方法論」之核心底稿。

🧩 元件 C：資安合規積木

檔名：`資訊安全維護政策規範.md`

包含公司標準資安切結條款與審計流程。直接套用為資格審查附件，無需人工重複撰寫與排版。

🏗️ 07. Antigravity 任務指令模板

展示 Agent 作為 「長文件執行器 (Long Document Runtime)」 時的工作邏輯

以下為 Antigravity 在進行長文件自動組裝時，所讀取的工程化指令母稿。這證明了 Agent 是在嚴密規則下進行操作，而非盲目寫作： 

# 任務：長文件元件化組裝與回應索引建立
[角色]：你現在是 AIDE 長文件工程執行器。
[輸入]：讀取 `/01_招標進件` 的 RFP 與 `/02_歷史資產` 下的所有知識元件。
[執行步驟]：
1. 比對 RFP 中的 REQ-02 (專案方法論) 要求。
2. 調用 `skyline_pm_methodology.md` 作為核心方法論底稿。
3. 自動比對並組裝出一份 2000 字的「專案執行方法論_草稿.md」。
4. 在撰寫過程中，必須引用「流程映射」與「小幅增強」的白話案例，確保名詞前後一致。
5. 嚴禁編造不存在的實績，若有缺件，請在檔案頂部輸出 [RISK_ALERT]。
6. 自動套用標準 Markdown 目錄與政府建議書格式排版。

👑 08. 總經理 (Grace) 專屬指令指揮卡

高階主管 「不需要記程式碼」，只需在關鍵節點複製指令，即可行使絕對指揮權

🏁 階段一：動手前的計畫審查 (Plan Check)

在 Agent 開始做事之前，先對齊理解與步驟

請先不要急著寫建議書正文。請先列出你理解的招標核心需求，以及你預計要調用哪些歷史資產積木，列出工作步驟等我核准。

🔍 階段二：合規與風險稽核 (Compliance Audit)

在起草過程中，命令 Agent 進行自我稽核比對

請幫我比對 120 頁的招標規範書，列出一份回應對照表。並用最醒目的方式標示出目前有哪些高風險缺件，或是不合規的地方。

✍️ 階段三：語氣與術語微調 (Tone Refinement)

要求長文件的前後名詞與口吻高度一致

請把這章方法論草稿修改為正式、嚴謹的政府標案語氣。注意名詞必須與我們公司的『Skyline PM』與『流程映射』術語高度一致，並保留事實的參考出處。

📊 階段四：專案收攏與責任指派 (Wrap-Up)

準備提交前，進行成果收攏與下一步指派

請把目前的執行成果、已完成章節、剩餘缺件與風險，整理成一份給我的中控摘要，並指出下一個動作是誰的責任。

🕹️ 09. 為什麼最後需要 Skyline PM 知識中控？

單次標案可以用 Antigravity 升級，但長遠的經營需要 「知識資產中控中心」

💡 工具是手段，管理才是目的

當我們學會用 Antigravity 解決招標書「怎麼做」之後，星河面臨的更長遠的營運課題是：如果每週、每月都有數個專案與標案在同時運作，主管如何監控全局？人員突然異動該如何交接？

Skyline PM 在長效治理中扮演的四大核心防線價值：

🚦 主動避險與紅綠燈

專案重要文件是否缺件？人員異動是否會造成大腦資料庫斷層？看板以最直觀的紅綠燈主動警告主管，將被動等待改為主動防守。

🧠 新人無痛自主接手

歷史案卷的所有 QA 庫隨時可查，新人進來直接詢問中控中心大腦，獲得帶有文獻引證的答覆，老鳥完全不用手動帶新人。

🔄 資產持續滾動累積

每次標案產出的新元件、克服的新風險，都會自動知識資產化回收進大腦，作為下一個專案的積木，讓星河越做越輕鬆。
