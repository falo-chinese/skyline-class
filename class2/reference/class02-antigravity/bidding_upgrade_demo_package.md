# 🏗️ Antigravity 招標書作業升級示範包 (Bidding Upgrade Demo Package)

> **Skyline 雙軌治理工作母稿 (Markdown Master Draft)**  
> **課程主題**：從過去累積到未來價值 — 企業知識資產化與 AI 應用實務  
> **專用客群**：星河內訓 Class 02（總經理 Grace 實戰教案）  

本示範包是 Class 02 教學實作的「主秀」。它不談抽象代碼，而是將幾百頁的「招標書」視為一個嚴密的**長文件工程問題**，並向學員（特別是高階主管Grace）展示 **Antigravity (長文件工程執行器)** 如何實質重塑招標流程。

---

## 一、 招標書作業情境說明 (The Operation Scenario)

### 🏢 模擬企業：星河數位科技 (Skyline)
* **面臨任務**：參與政府 **「智慧政務文件數位化與知識工程導入專案」**（招標標案金額：新台幣 500 萬元）。
* **極限時間限制**：距離投標截止僅剩 **3 天**。
* **文件工程規模**：招標規範書（RFP）高達 **120 頁**，要求極度繁雜，包含公司背景、資安規範、歷史實績、專案執行方法論及多份合規資格附件。
* **傳統人工作業痛點**：
  * PM 手動翻閱 120 頁 RFP，容易漏掉角落的合規條款（例如：漏附某張資安證照）。
  * 拼裝舊標案時，因為不同人修改，造成專案方法論的名詞前後矛盾。
  * 總經理（Grace）無法即時看到目前的缺件狀態與合規風險，只能在最後關頭盲目蓋章。

## 二、 規範資料夾結構 (SME Workspace Architecture)

長文件工程的第一步是 **Knowledgeization (知識化)**，即建立 AI 與人類都能一眼看懂的乾淨目錄結構，拒絕混亂：

```text
星河_2026政府智慧文件標案/
├── 01_招標進件 [Input_RFP]/
│   ├── 智慧政務專案招標規範書_v1.0.pdf      // 120頁原始RFP
│   └── 招標需求抽取表.md                     // 由 Agent 自主分析產出
├── 02_歷史資產 [Reference_KM]/
│   ├── 星河公司簡介元件.md                 // 可重用知識元件
│   ├── 2025年鼎盛ERP專案實績.md               // 可重用歷史實績
│   └── 資訊安全維護政策規範.md               // 歷史合規文件
├── 03_組裝章節 [Output_Chapters]/
│   ├── 01_建議書首頁.md
│   ├── 02_專案執行方法論_草稿.md            // 本次實作產出示範章節
│   └── 03_歷史績效與資安證明.md
└── 04_中控管理 [Skyline_PM]/
    ├── 標案合規對照表_Compliance_Matrix.md  // 本次產出
    └── 專案中控儀表板.html                   // 管理者天眼
```

## 三、 招標需求抽取表 (RFP Requirements Extraction)

當我們把 120 頁的 `智慧政務專案招標規範書_v1.0.pdf` 拖入大腦後，**Antigravity** 自主抽取出的四大合規核心需求：

| 規範編號 | 招標要求項目 | 規範細節 | 權重/懲罰 |
| :--- | :--- | :--- | :--- |
| **REQ-01** | 公司基本實績證明 | 投標廠商須於過去 3 年內具備至少 1 案金額達 300 萬元以上之文件數位化或知識工程實績。 | 資格審查門檻 (扣分/資格不符) |
| **REQ-02** | 專案執行方法論 | 建議書須詳述「文件數位化流程」與「知識資產化轉化路徑」，並說明品質把關機制。 | 評選評分項目 (30%) |
| **REQ-03** | 資訊安全防護防線 | 投標廠商須證明符合基本資安規範，並檢附資安政策切結書。 | 資格審查門檻 (資格不符) |
| **REQ-04** | 財務狀況合規證明 | 須檢附過去 3 年經會計師簽證之財務報表，且負債比率不得高於 60%。 | 資格審查門檻 (資格不符) |

## 四、 Compliance Matrix / 回應對照表

這是長文件工程的靈魂。它建立了**「招標需求條文」**與**「公司既有資產」**之間的映射索引，確保每一條要求都有據可查：

| 🎯 招標需求 | 🚦 合規狀態 | 🔑 既有知識資產來源 | 🏗️ Antigravity 執行動作 |
| :--- | :--- | :--- | :--- |
| **REQ-01 (基本實績)** | **🟢 100% 合規** | 歷史資產 `/2025年鼎盛ERP專案實績.md` | 自動拉取鼎盛專案 450 萬實績數據，元件化組裝至標書第三章。 |
| **REQ-02 (方法論)** | **🟡 待組裝** | 參考文獻 `/skyline_pm_methodology.md` | 以「流程映射與知識中控」為核心，自動撰寫「專案執行方法論」草稿。 |
| **REQ-03 (資安證明)** | **🟢 100% 合規** | 歷史資產 `/資訊安全維護政策規範.md` | 提取資安條款，組裝並自動產生「星河資安切結書」草稿。 |
| **REQ-04 (財務證明)** | **🔴 高風險缺件** | **無對應歷史檔案** | 標記為高風險紅燈，於 PM 中控台亮燈警告，等待會計手動上傳。 |

## 五、 缺件與風險防線清單 (Risk & Exception List)

Agent 在背景進行自我稽核後，主動遞交給總經理Grace的避險報告：

> ### 🚨 【高風險紅燈】財務合規證明缺件 (REQ-04)
> * **風險描述**：招標規範第 18 頁明確要求檢附「會計師簽證財務報表」，若漏附將直接被判定為不合格廠商，直接退件。
> * **避險行動**：目前資料夾中沒有任何 2023-2025 的財報 PDF。系統已在中控台亮起紅燈，請Grace指派會計立即補件。

> ### ⚠️ 【中風險黃燈】鼎盛專案結案公文未歸檔 (REQ-01)
> * **風險描述**：雖然有 `鼎盛ERP專案實績.md` 母稿，但招標規範要求檢附「客戶驗收證明公文影本」。
> * **避險行動**：大腦檢索到公文尚未進行資產化。請 PM 於 24 小時內掃描公文並拖入大腦。

## 六、 可重用元件清單 (Reusable Chapters)

這代表星河的**「歷史累積價值」**。寫標案不再從零開始，而是如同堆積木：

1. **元件 A：星河基礎資格積木** ➔ `星河公司簡介元件.md`（包含公司背景、資本額、統一編號，直接複用）。
2. **元件 B：標案執行方法論積木** ➔ `skyline_pm_methodology.md`（將「流程映射」與「知識中控」的方法直接作為方法論的底稿）。
3. **元件 C：資訊安全政策積木** ➔ `資訊安全維護政策規範.md`（公司制式資安聲明，一鍵套用）。

## 七、 Antigravity 任務指令模板 (Agent Task Prompts)

這是 Agent 作為 **Long Document Runtime (長文件執行器)** 時在背景運行的指令。讓學員理解，指令不是叫 AI 寫文章，而是進行**工程操作**：

```markdown
# 任務：長文件元件化組裝與回應索引建立
[角色]：你現在是 AIDE 長文件工程執行器。
[輸入]：讀取 `/01_招標進件` 的 RFP 與 `/02_歷史資產` 下的所有知識元件。
[執行步驟]：
1. 比對 RFP 中的 REQ-02 (專案方法論) 要求。
2. 調用 `skyline_pm_methodology.md` 作為核心方法論底稿。
3. 自動比對並組裝出一份 2000 字的「專案執行方法論_草稿.md」。
4. 在撰寫過程中，必須引用「流程映射」與「小幅增強」的白話案例，確保名詞前後一致。
5. 嚴禁編造不存在的實績，若有缺件，請在檔案頂部輸出 [RISK_ALERT]。
```

## 八、 一頁式總經理（Grace）指令卡 (GM Command Card)

> **這是一張送給Grace的「防呆與權力指引卡」。**
> Grace上課不需要學寫 code 或繁雜的 prompt。她只需要在關鍵節點，複製以下白話指令給 AI，就能完美行使**「管理者審查與指揮權」**：

### 🏁 階段一：動手前的計畫審查 (Plan Check)
當 Agent 準備開始時，Grace使用：
> 💬 **「請先不要急著寫建議書正文。請先列出你理解的招標核心需求，以及你預計要調用哪些歷史資產積木，列出工作步驟等我核准。」**

### 🔍 階段二：合規與風險稽核 (Compliance Audit)
在生成過程中，Grace使用：
> 💬 **「請幫我比對 120 頁的招標規範書，列出一份回應對照表。並用最醒目的方式標示出目前有哪些高風險缺件，或是不合規的地方。」**

### ✍️ 階段三：語氣與術語微調 (Tone & Style Refinement)
在審閱草稿時，Grace使用：
> 💬 **「請把這章方法論草稿修改為正式、嚴謹的政府標案語氣。注意名詞必須與我們公司的『Skyline PM』與『流程映射』術語高度一致，並保留事實的參考出處。」**

### 📊 階段四：專案收攏與收尾 (Wrap-Up)
準備提交前，Grace使用：
> 💬 **「請把目前的執行成果、已完成章節、剩餘缺件與風險，整理成一份給我的中控摘要，並指出下一個動作是誰的責任。」**

## 九、 Skyline PM 收束：為什麼我們需要知識中控？

### 🎯 最終引導思維

Antigravity 幫星河解決了**「單次招標書如何高效率、高品質產出」**的工程問題。

但隨著投標案量增加、專案持續運作，Grace會面臨更長遠的管理挑戰：
* 「這次標案的成果，如何變成下次標案的資產？」
* 「PM 請假了，誰知道這份建議書修改到第幾版？」
* 「會計補件了沒有？風險紅燈排除了嗎？」

這就自然導向了 **Skyline PM (知識資產中控中心)**：

```
單次招標作業 (Antigravity 長文件 Runtime)
      │
      ▼ (高頻、多專案、日常化)
專案與資產長效治理 (Skyline PM 知識資產中控中心)
      │
      ├─ 🟢 進度透明：主管不用催，看板直接亮進度。
      ├─ 🔴 主動避險：缺件、風險紅綠燈自動警示。
      ├─ 🟣 無痛交接：歷史脈絡與大腦 QA 隨時可查，新人 5 分鐘上手。
      └─ 🔵 資產滾動：每次標案新知識，自動回收進大腦，越做越輕鬆。
```

這不是多導入一套軟體，而是把星河既有的檔案管理與進度，映射為一個能讓企業長效傳承的**安全中控防線**。
